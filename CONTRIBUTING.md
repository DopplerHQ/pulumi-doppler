# Contributing to the Doppler Pulumi provider

This provider is generated from [terraform-provider-doppler](https://github.com/DopplerHQ/terraform-provider-doppler) by the [Pulumi Terraform bridge](https://github.com/pulumi/pulumi-terraform-bridge). Bugs in resource behavior usually belong upstream; changes here are about how resources map into Pulumi, the SDKs, and CI.

## Code of Conduct

Please read and follow our [Code of Conduct](./CODE-OF-CONDUCT.md).

## Setting up your development environment

The Makefile installs every tool it needs with [mise](https://mise.jdx.dev/), at the versions pinned in `.config/mise.toml` (generated by ci-mgmt) and `mise.toml` (our overrides). Install mise, then run make targets through `mise exec` so tools resolve to those versions even when tfgen runs them outside the repository:

```bash
mise install
mise exec -- make build
```

## Committing generated code

Pull requests that change `provider/resources.go` or the upstream version must include the regenerated schema and SDKs:

1. Run `mise exec -- make schema`, then `mise exec -- make generate_sdks`. SDK generation reads the committed `provider/cmd/pulumi-resource-doppler/schema.json`, so regenerate the schema first.
1. Run `mise exec -- make build_sdks lint_provider` to check that the SDKs compile and the provider passes lint.
1. Commit `schema.json`, `bridge-metadata.json` and everything under `sdk/`.

If a large number of seemingly unrelated diffs appear, run `go mod tidy` in `provider/` so the dependencies match `go.mod`.

## CI configuration

The workflows under `.github/` and much of the Makefile are generated by [pulumi-labs/ci-mgmt](https://github.com/pulumi-labs/ci-mgmt). Don't edit them directly: change `.ci-mgmt.yaml` and run `make ci-mgmt`.

## Running integration tests

The tests in `examples/` create and delete real resources in a Doppler workplace. See [examples/README.md](./examples/README.md) for how to run them.
